MODULE 01

User Registration & Login

User ka app ke andar sabse pehla interaction — naya account banana, purane account me login karna, password bhool jana, aur profile edit karna.

A. New user — Registration (account banana)

User pehli baar app kholta hai aur "Register" choose karta hai.

1
User"Register" button pe click karta hai, apna name, email/phone, password type karta hai, "Customer" ya "Provider" role choose karta hai.
2
TechReact Hook Form + Zod — frontend pe hi turant check karta hai ke email sahi format me hai, password kam se kam 8 characters ka hai, koi field khali nahi. Galat hone pe turant error dikhata hai, server tak request jati hi nahi.
3
User"Create Account" button dabata hai — form submit hota hai.
4
BackendNestJS API request receive karta hai — pehle check karta hai ke email/phone pehle se database me exist to nahi karta (duplicate account rokne ke liye).
5
Techbcrypt (via Firebase Auth / Auth0's built-in hashing) — password ko plain text me kabhi save nahi karta, hash bana kar store karta hai taake database leak hone par bhi password safe rahe.
6
DBPostgreSQL — naya row insert hota hai users table me.
users [ id, name, email, phone, password_hash, role (customer/provider), is_verified, created_at ]
7
BackendOTP generate hota hai aur SMS/email pe bhejta hai — verification ke liye (agla feature dekhein).
Lean AltAgar khud ka backend auth system banana time-consuming lage, to poora ye step "Firebase Auth" ek hi free SDK se kar sakte hain — duplicate check, password hashing, sab automatically ho jata hai, koi custom NestJS auth code likhne ki zaroorat nahi.

B. OTP Verification (naya account confirm karna)

1
UserPhone/email pe aya hua 6-digit code type karta hai.
2
Techspeakeasy — backend pe generate kiya gaya secret ke against, user ne jo code dala hai usay verify karta hai (speakeasy.totp.verify()).
3
DBPostgreSQL — is_verified column ko true update karta hai.
4
BackendVerification successful hone par account activate hota hai aur user seedha login/home screen pe redirect hota hai.

C. Existing user — Login (purana account)

1
User"Login" button pe click karta hai, email/phone + password enter karta hai.
2
BackendNestJS — database me email/phone search karta hai, phir daale hue password ka hash, stored hash se compare karta hai.
3
TechJWT (jsonwebtoken) — password match hone par ek access token (15 min valid) aur refresh token (7 din valid) generate karta hai.
4
TechRedis — session ko cache me store karta hai, taake har request pe baar baar PostgreSQL se user check na karna pade. "Ye user already login hai" — bina database scan kiye, sirf Redis se pata chal jata hai, jis se login bohat fast ho jata hai.
5
UserToken receive hota hai app me (Expo SecureStore me save hota hai), user home screen pe pohanch jata hai.
Redis key: session:{user_id} → { token, role, last_active }  |  TTL = access token expiry

D. Password Reset (password bhool jana)

1
User"Forgot Password" click karta hai, apna email/phone daal ta hai.
2
Techspeakeasy — ek time-limited reset OTP generate karta hai, SMS/email se bhejta hai.
3
UserOTP verify karta hai, naya password type karta hai (2 baar — confirm ke liye).
4
BackendNaya password hash hota hai, PostgreSQL me password_hash column update hota hai, purane saare active tokens/sessions Redis se turant remove ho jate hain (security ke liye — taake koi purana session valid na rahe).

E. Profile Edit (name, email, phone, profile picture update)

1
User"Edit Profile" screen kholta hai, name/phone/picture change karta hai, "Save" click karta hai.
2
TechReact Hook Form + Zod — dobara validate karta hai (e.g. phone number format sahi hai ya nahi).
3
TechProfile picture ho to AWS S3 / Cloudflare R2 pe upload hoti hai, sirf uska URL database me save hota hai (image khud database me kabhi nahi jati).
4
DBPostgreSQL — users table ka relevant row update (UPDATE query) hota hai; Redis cached session bhi refresh hota hai naye data ke sath.
MODULE 02

Voice-Powered Booking, Voice Chat & AI Assistant

User bolke apni service book karta hai — Urdu, English ya Roman Urdu me, aur AI samajh kar booking bana deta hai.

A. Voice Booking — recording se booking tak

1
UserMic button dabata hai aur bolta hai: "mujhe plumber chahiye kal shaam DHA phase 2 me, budget 3000 tak".
2
TechRNNoise — recording se background noise (traffic, TV, etc.) hata deta hai transcription se pehle.
3
TechWhisper (OpenAI, self-hosted) — audio ko text me convert karta hai (speech-to-text). Ye aapke original list me missing tha, is liye add kiya hai.
4
TechfastText / langdetect — transcribed text check karta hai ke Urdu hai, English hai, ya Roman Urdu — taake sahi NLP pipeline chune.
5
TechspaCy — text se important cheezen nikalta hai: service_type = plumber, location = DHA Phase 2, date = tomorrow evening, budget = 3000.
6
BackendExtracted data se ek draft booking banti hai, user ko confirm karne ke liye screen pe dikhai jati hai.
7
UserDraft check karta hai, "Confirm Booking" dabata hai.
8
DBPostgreSQL — booking table me naya row create hota hai.
bookings [ id, customer_id, provider_id (null until matched), service_type, location, scheduled_time, budget_estimate, status, source (voice/text), created_at ]
Lean AltRNNoise ko skip kar sakte hain — Whisper khud hi halke background noise ko theek se handle kar leta hai; sirf tab add karein agar demo recordings me noise real problem ban raha ho.

B. AI Assistant — chat se reply karna

1
UserAssistant se sawal poochta hai (voice ya text) — jaise "kya mera booking confirm ho gaya?"
2
TechHugging Face DistilBERT (fine-tuned) — is sentence ka intent classify karta hai: booking-status-query.
3
BackendDistilBERT ke intent ke mutabiq, database se related booking data fetch hota hai.
4
TechFree-tier LLM API (Gemini/Groq) — fetched data ko ek natural, friendly reply sentence me convert karta hai user ki apni language me.
5
TechSocket.io — reply turant, real-time chat screen pe deliver hota hai, bina refresh kiye.
MODULE 03

Home Renovation Planning (Text Mode)

User type kar ke apna renovation idea batata hai, app usay ek structured plan me convert karta hai.

Renovation request se plan tak

1
UserChat box me type karta hai: "apni kitchen renovate karwani hai, budget 50 hazar hai".
2
TechspaCy — room = kitchen, budget = 50000 extract karta hai.
3
BackendRule-based engine (PostgreSQL me stored rules) check karta hai: "kitchen renovation" ke liye typically electrician → tiler → painter → plumber, is order me chahiye hota hai.
4
TechFree LLM API — is structured plan ko ek achi, samajhne wali sentence me likh kar user ko dikhata hai.
5
UserPlan dekh kar, jo services chahiye un me se select karta hai → har selection ek alag booking (Module 7) bana deta hai.
MODULE 04

Multimodal Damage & Appliance Assessment

User photo ya video bhejta hai kharab cheez ki, AI batata hai masla kya hai.

Photo se problem identify karna

1
UserCamera icon click karta hai, kharab appliance/pipe/wall ki photo khenchta ya gallery se choose karta hai.
2
TechYOLOv8 — photo me object detect karta hai (e.g. "washing machine", "leaking pipe joint") aur uske around box draw karta hai.
3
TechTesseract OCR — agar label/serial number/model number visible hai to detected region se text extract karta hai.
4
TechLLaVA (ya free hosted Gemini Vision) — photo dekh kar plain-language description deta hai: "yeh pipe joint se paani leak ho raha hai, seal kharab lag rahi hai".
5
TechCLIP (optional) — is photo ko purani "known issues" photos se compare kar ke closest matching problem suggest karta hai.
6
DBPhoto S3/R2 pe upload hoti hai, detection result PostgreSQL me booking se link hota hai.
damage_reports [ id, booking_id, image_url, detected_object, ocr_text, ai_description, confidence_score ]
Lean AltCLIP skip kar ke sirf YOLOv8 ka detected label + LLaVA/Gemini ki description hi kaafi hai MVP ke liye — CLIP baad me "visual search" feature ke liye add kar sakte hain.

Video se proof-of-work / damage assessment

1
UserChhoti video upload karta hai (damage dikhane ke liye, ya provider "job complete" proof ke liye).
2
TechFFmpeg — video ko compress karta hai aur har 2 second pe ek frame nikal ta hai.
3
TechHar frame Module 4's photo pipeline (YOLOv8 → Tesseract → LLaVA) se guzarta hai, dobara alag video-model banane ki zaroorat nahi.
MODULE 05

Dynamic Pricing Engine

Request se price estimate tak

1
BackendVoice/text booking se already extracted service_type, location, urgency, date (Module 2/3 se — spaCy output) use hota hai.
2
TechRule-based pricing formula: base_price[service_type] × distance_factor × urgency_factor × time_of_day_factor.
3
DBPostgreSQL — base rates ek pricing_rules table se read hote hain, jo aap khud tune kar sakte hain.
pricing_rules [ service_type, base_price, urgency_multiplier, night_multiplier ]
4
UserEstimated price range screen pe dikhta hai booking confirm karne se pehle.
MODULE 06

Intent Recognition & Request Routing

Message type pehchan kar sahi jaga bhejna

1
UserKoi bhi message type/bolta hai — booking ho, complaint ho, ya cancellation.
2
TechDistilBERT (fine-tuned classifier) — decide karta hai: booking / complaint / reschedule / cancel / general question.
3
TechspaCy — us intent ke liye zaroori entity nikalta hai (jaise cancel ke liye booking ID).
4
BackendRequest sahi handler/screen ki taraf route hoti hai — e.g. cancel-intent seedha cancellation flow trigger karta hai.
MODULE 07

Provider Scheduling & Booking Management

Provider apni availability set karta hai

1
User (Provider)"My Schedule" screen kholta hai, available dates/times select karta hai.
2
Techreact-native-calendars — month view dikhata hai, selected dates highlight hote hain.
3
DBPostgreSQL — har slot ek row banta hai.
availability [ id, provider_id, date, time_slot, is_booked ]

Customer slot book karta hai

1
User (Customer)Provider ki calendar dekh kar ek free slot pe click karta hai.
2
BackendNestJS — us slot ko atomically lock karta hai (transaction ke sath) taake do log ek hi slot na book kar saken.
3
DBis_booked = true update hota hai, naya row bookings table me banta hai.

Rescheduling

1
User"Reschedule" click karta hai, calendar se naya slot chunta hai.
2
TechBullMQ (Redis-backed queue) — background me doosre party ko notification bhejta hai, taake API response instantly wapis aaye.

Booking Verification (arrival confirm karna)

1
User (Provider)Location pe pohanch kar apna QR code dikhata hai / customer ka QR scan karta hai.
2
Techreact-native-qrcode-svg — unique QR generate karta hai booking ID encode kar ke; scan hone par booking status "started" ho jata hai.

approvals [ id, booking_id, type (price_accept/work_complete), signature_url, timestamp ]

MODULE 10

Trust & Safety — Fraud, Fake Accounts & Fake Reviews

Fake account network detect karna

1
BackendBackground job (daily) chalta hai jo saare accounts ka data (device ID, phone, payment info) fetch karta hai.
2
TechNetworkX — har user/provider/device ko ek "node" banata hai, shared attributes (same device, same payment method) ko "edge" banata hai; phir clusters dhoondta hai jo ek hi insan ke multiple fake accounts lag rahe hon.
3
DBSuspicious accounts ek flags table me maark hote hain, admin panel me review ke liye.
fraud_flags [ id, user_id, reason, cluster_id, flagged_at, reviewed ]

Fake review detect karna

1
UserReview submit karta hai (rating + text).
2
TechDistilBERT — text ke pattern check karta hai (generic, template-jaisa, duplicate to nahi).
3
TechNetworkX — check karta hai ke reviewer suspicious cluster ka hissa to nahi.
4
BackendSuspicious lagne par review "pending moderation" me chala jata hai, public nahi hota jab tak review na ho.

Urdu/Roman Urdu review sentiment score karna

1
TechfastText — review ki language detect karta hai.
2
TechUrdu/Roman Urdu ho to Urdu Sentiment Lexicon se score hota hai (positive/negative words count); English ho to DistilBERT se.
MODULE 11

Ratings, Reviews & Community (Chat, Comments)

Chat message bhejna (profanity filter ke sath)

1
UserMessage type kar ke "Send" dabata hai.
2
Techbetter-profanity — message store/broadcast hone se pehle server pe check hota hai, gaali/abusive words censor ya block ho jate hain.
3
TechSocket.io — clean message doosre user tak real-time pohanch jata hai.

Review dena

1
UserCompleted booking pe stars + comment daal kar submit karta hai.
2
TechReact Hook Form + Zod — form validate karta hai; better-profanity comment check karta hai.
3
DBPostgreSQL — review save hota hai, sirf un customers se accept hota hai jinki booking fill "completed" hai (fake review rokne ka basic tareeqa).

MODULE 13

App Shell, Backend & Infrastructure

Ye woh scaffolding hai jis ke andar upar ke saare 12 modules chalte hain.

LayerTechFYP Note
Mobile AppReact Native + Expo + TypeScriptKeep — fastest way to a real installable app.
NavigationReact NavigationKeep — standard choice.
StateZustandKeep — less boilerplate than Redux for solo/small team.
Data FetchingTanStack QueryKeep — handles loading/error/retry automatically.
BackendNode.js + NestJSKeep if comfortable with TS OOP; Express.js is a lighter alt.
DatabasePostgreSQL + PrismaKeep — type-safe queries, easy migrations.
Cache/QueueRedis + BullMQKeep — free self-host, simpler than Kafka for FYP scale.
StorageCloudflare R2 (cheaper than S3)Prefer R2 for a student budget.
HostingRailway / Render / Fly.ioSkip full AWS ECS/K8s — overkill for FYP scope.
MonitoringSentry (free tier)Keep — genuinely useful, demoable.
CI/CDGitHub Actions + EAS BuildKeep — free, gives installable APK for defence.
